### **[1] Refactorización y Code Smells**

#### **1.a) Code Smells y Patrones de Refactorización Aplicados**
Los principales **code smells** corregidos y los **patrones de refactorización** utilizados fueron:

1. **Código muerto/incompleto (`TODO()`)**
    - **Smell:** Métodos sin implementar (`logStateChange`, `logAssignmentChange`, etc.).
    - **Refactorización:** Implementación completa de los métodos.
    - **Enlace al código:** [`HistorialRepository.kt`](#) (implementación de los métodos).

2. **Nombres no estandarizados (`añadirModificationEstado`)**
    - **Smell:** Uso de caracteres no ASCII y notación inconsistente.
    - **Refactorización:** **Renombrar método** (`añadirModificationEstado` → `anadirModificacionEstado`).
    - **Patrón:** *Rename Method* (mejora legibilidad).
    - **Enlace al código:** [Línea modificada](#).

3. **Propiedades no inicializadas (`tareas: Any` en `Usuario`)**
    - **Smell:** Riesgo de `NullPointerException`.
    - **Refactorización:** Inicialización con valor por defecto (`= Any()`).
    - **Patrón:** *Initialize Properly*.

---

#### **1.b) Patrón Cubierto por Tests y su Impacto**
**Patrón seleccionado:** *Implement Method* (para eliminar `TODO()` en `logStateChange`).

**¿Por qué mejora el código?**
- **Antes:**
  ```kotlin
  override fun logStateChange(...) { TODO() }  // ❌ Falla en runtime
  ```  
- **Después:**
  ```kotlin
  override fun logStateChange(estado: Estado, tarea: Tarea, ...) {
      historialEstados.add("Cambio a ${estado.descripcion}")  // ✅ Funcionalidad real
  }
  ```  
- **Beneficios:**
    - Elimina código inseguro (`TODO()`).
    - Permite que los tests verifiquen el comportamiento real.
    - **Test asociado:** [`HistorialRepositoryTest`](#) (verifica que se registran cambios).

### **[2] Proceso para Evitar Regresiones**

#### **2.a) Pasos para Garantizar Estabilidad**
1. **Ejecutar pruebas antes de refactorizar:**
   ```bash
   ./gradlew test  # Verificar que todo funciona
   ```  
2. **Refactorizar en pasos pequeños:**
    - Ejemplo: Primero implementar `logStateChange`, luego ejecutar tests.
3. **Uso de herramientas del IDE:**
    - **IntelliJ** → **Refactor → Rename/Safe Delete** (valida usos del código).
4. **Pruebas después de cada cambio:**
   ```bash
   ./gradlew test --tests "*.HistorialRepositoryTest"  # Tests específicos
   ```  
5. **Git para reversiones:**
    - `git commit` frecuentes para poder volver atrás si hay errores.

#### **3.a) Funcionalidades del IDE Usadas**

4. **Análisis de código en tiempo real:**
